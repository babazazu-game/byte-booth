# Инструкция для ИИ-агента

Этот файл читают Codex, Cursor, Amp и другие агенты. Claude Code читает
`CLAUDE.md`, который ссылается сюда же. Правила одни для всех.

## Что это

Заготовка новой игры под **Яндекс.Игры** на Three.js + TypeScript + Vite.
Не абстрактный шаблон: это вытяжка из игры «МикроБум» (`three-in-stack`),
доведённой до релиза. Всё, что здесь лежит, уже прошло модерацию площадки
и правку по её замечаниям.

## Три слоя, и их нельзя смешивать

| Слой | Где | Отвечает за |
|---|---|---|
| Каркас площадки | `yg-core` (соседний репозиторий) | SDK, реклама, сохранения, язык, рейтинги, safe-area, HiDPI |
| Системный слой игры | `src/*.ts` | ПРАВИЛА игры относительно площадки: где звать рекламу, что хранить в прогрессе |
| Игра | `src/game.ts` и рядом | сцена, механика, уровни |

**Правило:** нашёл общую проблему площадки — чини в `yg-core`, а не в игре.
Нашёл механику — она не имеет права знать про SDK.

`yg-core` подключается **исходниками** через алиас в `vite.config.ts`, а не
через npm. Правка в каркасе сразу видна во всех играх; обратная сторона —
сломав каркас, ломаешь все игры разом, поэтому перед коммитом в нём гоняется
`npm run typecheck`.

## Команды

```bash
npm install        # первый раз
npm run dev        # разработка, http://127.0.0.1:5170
npm run build      # проверка типов + сборка в dist/
npm run zip        # сборка + архив для площадки в build/
```

## Правила проекта

1. **Комментарии и коммиты — на русском.** Комментарий объясняет ПОЧЕМУ так,
   а не что делает строка. Особая ценность — записанные грабли: «делали
   иначе, вот что сломалось».
2. **Логика отдельно от рендера.** Правила игры — чистые функции над
   состоянием, без единого обращения к Three.js. Это даёт тесты и солвер даром.
3. **Раскладка считается от краёв внутрь**, с учётом safe-area. Позиционировать
   как «край экрана плюс сколько-то» нельзя: именно так элементы уезжают
   за границу, а это нарушение п. 1.10.1.
4. **Интерфейс верстается от высоты**: `u = H / UI_BASE_H`. Не от ширины —
   ландшафтные экраны различаются по ширине втрое, по высоте почти нет.
5. **Кегль и зона нажатия — через `fontPx()` и `tapSize()`.** Поднимать общую
   единицу интерфейса ради читаемости НЕЛЬЗЯ: на этом уже обжигались, раздулось
   всё разом и окна перестали помещаться на экран.
6. **Цикл кадров — `renderer.setAnimationLoop`**, не `requestAnimationFrame`.
   Разница не косметическая: только первый работает в VR/AR-сессии и
   корректно останавливается.
7. **Никаких абсолютных путей**, кроме `/sdk.js` в `index.html`.

## Требования площадки

Единый источник правды — `YANDEX_GAMES_REQUIREMENTS.md` (лежит в рабочей
папке серии игр). Пункты, на которых эта команда уже получала отказы:

- язык из SDK **до первого рендера UI** (п. 2.14), а не `navigator.language`
  с переключением постфактум;
- ничего не обрезается ни в одной ориентации (п. 1.10.1);
- `LoadingAPI.ready()` — когда меню реально видно, но не позже 90 секунд
  (п. 1.19.2);
- ZIP **только с прямыми слешами**, иначе 404 на всех вложенных файлах.
  Для этого есть `tools/make_zip.py`, штатным упаковщиком Windows не собирать;
- реклама не блокирует прогресс (п. 4.5.2): всё, что за ролик, — бонус.

## Перед заливкой

1. `src/dev.ts` — все флаги в `false`.
2. `npm run zip`.
3. Прогнать внешний чекер Яндекс.Игр, затем проверить руками во всех
   ориентациях: портрет и ландшафт телефона, планшет, десктоп.

## Чего здесь пока нет

Интерфейса. В Phaser-заготовке кнопки и окна рисуются на холсте, в Three.js
так не делают — интерфейс кладут DOM-слоем поверх канваса. Первая 3D-игра
этот слой и напишет; когда он заработает, его надо вернуть сюда, в заготовку.
Пределы из `yg-core` (`fontPx`, `tapSize`) действуют и для DOM: 13 px кегля
и 44 px зоны нажатия — требования площадки, а не движка.

## Чего не делать

- Не переписывать `src/audio.ts`, `src/sceneFlow.ts` и `watchSize()`
  в `main.ts` без крайней нужды: там записаны конкретные грабли движка,
  и «упрощение» возвращает их обратно.
- Не удалять комментарии-разборы. Они дороже кода: код очевиден, а причина,
  по которой он такой, — нет.
- Не заводить вторую точку доступа к прогрессу или к SDK. Их по одной,
  и это намеренно.
